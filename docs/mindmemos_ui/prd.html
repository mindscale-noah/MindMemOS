PRODUCT REQUIREMENTS · V0.1

Skill 工作台

用户继续日常聊天，在工作台中演进 Skill、管理图谱，让合适的 Skill 用到下一次任务中。

记忆系统持续负责轨迹采集、记忆抽取与检索注入；新增 Skill 算法库负责训练、无监督演进与图谱推荐。

普通用户：UI 演进与图管理开发者：CLI 训练默认：本地工作台 + 已有记忆服务
00

用户从哪里开始

安装后运行 mindmemos-ui，自动打开浏览器。用户无需进入源码目录，也无需单独启动算法服务。

接入记忆→绑定 Skill→日常聊天→一键演进→确认采用

首页进入「Skills」。一级导航为 Skills / Skill 图谱 / 任务 / 设置。训练不提供 UI 配置入口；CLI 产出的 Skill 可进入同一工作台管理。

「自动演进」指算法从无人工反馈的轨迹中生成候选版本。首版由用户点击触发，生成后由用户决定是否采用。
01

首次打开与配置

首次向导分两步：连接记忆服务、配置算法模型。完成后进入 Skills；已配置的用户只补缺失项。

1

连接记忆服务

填写服务地址与访问凭证，选择有权限的项目，点击「验证并继续」。已有 SDK 配置时自动填入地址并显示「凭证已保存」。

系统校验身份与项目权限，读取已有 Skill 和绑定关系。记忆服务的访问凭证与模型 API Key 分开保存。可跳过此步先管理本地 Skill；基于聊天轨迹的演进需完成连接。

2

设置算法使用的模型

选择提供方，填写 模型名称、API Key；服务地址使用提供方默认值，自定义服务可修改 URL。点击「测试并保存」。

默认将此连接用于演进和图谱中的文本模型调用。图谱算法需要向量模型时，向导单独要求选择可用的向量模型连接。

内置算法声明所需模型能力、默认参数和可编辑字段，UI 据此生成表单。提供方可列举模型时提供下拉选择，否则允许手填。测试说明会发送极短请求、可能产生少量费用，按所需能力校验，不只测试地址连通。

已有 YAML / .env 怎么处理？

自动识别约定工作空间中的配置；其他位置由用户主动选择文件。展示可导入的连接及参数，密钥始终遮蔽；来源冲突时由用户选择。导入后作为工作台管理的配置副本，保留源文件。未识别字段原样保留并提示；不静默改写旧配置。

用户以后改配置，需要改哪些地方？

在「设置 → 模型连接」修改一次，各算法通过连接引用复用。每个功能显示当前连接，可单独覆盖；高级参数默认折叠。优先级为本次任务覆盖 → 功能设置 → 工作台默认 → 算法默认。缺少必要字段时直接跳到对应表单，不让用户自行找 YAML。

后端生成算法实际配置，密钥以受限凭证存储中的引用注入，不写入前端响应、普通配置导出或日志。任务固定非敏感配置快照与凭证版本引用；运行中修改设置只影响新任务。已有 .env 导入值不再暗中覆盖 UI 保存值。

聊天插件由用户在工作台之外自行安装和配置。UI 不参与插件安装、连接、检测或采集控制，也不感知插件状态。UI 中的模型设置只作用于选定执行端的 Skill 算法；已有记忆服务的模型仍由服务端管理。
02

绑定 Skill，积累演进素材

1

添加或选择 Skill

在「Skills」选择已有 Skill；也可选择本机 Skill 目录，预览内容后添加。

已存在的云端 Skill 按稳定身份关联，不能按同名自动合并。导入本地内容时保留来源路径和版本。

2

关联记忆服务中的 Skill

选择记忆服务中对应的 Skill，确认关联。已有绑定直接复用；需要注册本地 Skill 时，先预览将上传的内容。

工作台依据服务端 Skill 身份与版本读取绑定和轨迹，不建立插件连接。聊天工具侧的 Skill 使用与配置由用户在工作台外完成。

3

照常聊天，在工作台查看积累结果

用户自行配置的聊天插件继续上报轨迹，记忆系统抽取记忆，并在后续聊天检索、注入。这个过程独立于 UI；用户无需打分、标注或准备训练集。

记忆系统判断轨迹是否使用了已绑定 Skill，符合条件时记录 skill binding。它关联实际使用的版本；仅绑定、被推荐或被注入，都不能直接等同于已使用。

4

查看可演进素材

Skill 详情展示记忆服务返回的「新增可用轨迹」、最近轨迹时间和摘要。没有素材时显示「暂无可用轨迹」；只有服务端提供明确原因时才进一步说明。

素材按项目与绑定身份隔离，只向有权限的用户展示。没有轨迹不能据此判断插件未安装、未连接或采集失败；UI 不展示此类推断状态。

03

从轨迹演进，再决定采用

1

点击「演进」

默认使用尚未处理的可用轨迹。确认页展示基准版本、素材数量与时间范围、使用模型、运行位置。用户可调整时间范围；算法参数放在「高级设置」。

默认在本机执行，从记忆服务读取授权轨迹，并将必要内容发送到所选模型服务。确认页明确数据去向；无法可靠预估费用时直接说明，不展示虚构价格。

2

查看运行状态

确认后进入任务详情，依次显示「准备素材 → 分析轨迹 → 生成版本 → 保存结果」。用户可离开页面、重新打开查看，或点击「停止」。

提交后立即返回任务 ID，耗时算法由受管理的执行进程运行。状态和阶段日志持久化；没有可靠总量时只显示阶段，不伪造百分比。无足够素材时结束为「暂无可演进内容」，不生成空版本。

3

审阅候选版本

完成后展示新旧内容差异、修改摘要和引用的轨迹依据。用户选择「采用版本」或「暂不采用」。

新版本先保存为候选，工作台当前选用版本保持不变。无监督演进不展示未经评测的提升分数，也不把生成成功解释为效果提升。

4

采用版本，按需导出

确认后将候选设为工作台当前选用版本。需要在聊天工具中使用时，选择目标目录、预览文件差异并导出；聊天工具侧的加载由用户自行完成。

UI 只显示可确认的「已采用 / 已同步 / 已导出」，不显示「聊天工具已加载」或「已生效」。本地存在用户修改时先解决冲突，保留旧版本。可从历史版本重新采用并导出。

失败、重试和重复点击

重复提交返回同一任务；相同素材不能被并发任务重复占用。失败后保留日志和已完成产物，支持重试；仅在候选版本可靠保存后提交素材处理记录。生成成功但暂不采用的素材仍标记为已处理，可显式选择重新演进。保存与记账须可重复执行，避免重试产生重复版本。

关闭页面不停止任务；本地服务退出后再次打开，显示真实的中断状态。有检查点才提供继续运行，否则从明确阶段重试。若运行期间基准版本变化，结果保留为候选并要求重新确认，不覆盖当前版本。

04

构建图谱，让新任务找到 Skill

1

选择 Skill，创建图谱

进入「Skill 图谱」，点击「创建」，命名并选择纳入的 Skill。默认引用已采用的明确版本，确认模型配置后开始构建。

图谱用于组织多个 Skill 及其关系，与单个 Skill 的版本历史分开展示。构建记录输入版本、配置和图谱快照；创建后可增减 Skill。

2

查看并试用推荐

点击节点查看 Skill 内容与版本。在「试用推荐」输入一条任务，查看推荐 Skill、推荐理由与对应内容。

推荐只来自当前用户有权访问且可用的 Skill；没有合适结果时显示「暂无合适 Skill」，不强制推荐。算法未提供可信分值时只展示排序和依据。

3

设置用于推荐的图谱

将图谱设为当前项目的推荐图谱。用户可继续在 UI 输入任务获取推荐；外部工具通过推荐接口接入，接入配置由用户在工具侧完成。

推荐服务对外提供接口，UI 只管理图谱与推荐设置，不选择、检测或控制插件，不展示「聊天已接入」。外部工具是否调用接口、是否加载推荐 Skill，不由 UI 推断。

4

Skill 更新后更新图谱

采用新 Skill 版本后，相关图谱显示「待更新」，用户点击更新。完成后后续任务使用新图谱，进行中的任务保持原快照。

更新期间继续使用上一份可用图谱；更新成功后切换。已删除或失去权限的 Skill 即时过滤，不能因旧快照继续推荐。

本地推荐服务需要保持运行。服务不可用时，聊天与已有记忆链路继续工作；需要持续在线推荐的用户可切换到已部署且支持相同能力的远程 Skill 服务。
05

训练通过 CLI 完成

编写并注册 Env→准备数据→CLI 启动训练→产出 Skill 版本→工作台管理与使用

开发者在代码中注册 Env、提供数据，通过 CLI 指定算法配置并启动训练。CLI 可复用工作台中的模型连接，也可显式指定自己的配置。

训练结果写入同一工作空间时自动出现在 Skills；来自其他环境时，通过「导入 Skill」进入工作台。用户随后可绑定、采用或加入图谱。

UI 不承担 Env 编写、数据集管理和训练参数编辑。导入结果保留训练来源及可用评测记录；训练分数与无监督演进结果分别展示。具体命令沿用 CLI 的正式接口，本文不定义新命令。

06

流程背后的产品架构

用户只启动一个工作台。现有记忆服务继续工作，新增算法能力通过统一服务接口接入。

交互入口

UI 与本地 FastAPI

同一服务提供网页和接口。负责配置向导、Skill 操作、任务状态与图谱展示。浏览器不直接连接数据库，也不保存模型密钥。

算法与执行

mindmemos_skill

提供训练、无监督演进与图谱推荐。轻量操作由 Python 服务直接执行；长任务进入受管理的执行进程。CLI 与 UI 复用同一算法服务和配置解析。

已有服务

mindmemos

保留记忆抽取、检索、轨迹与 skill binding。通过有权限校验的接口提供演进素材及结果关联；UI 不直接读取云数据库。

聊天现场

本地插件

由用户独立安装和配置，负责既有轨迹采集与记忆注入。外部工具可另行对接推荐接口；UI 不负责插件生命周期，不感知其安装、连接或加载状态。

用户遇到的变化产品方案
已有用户升级首次打开读取已有项目、Skill、版本与绑定，无需重新注册。新增模型能力缺失时仅补充配置，不影响原记忆链路。
原 skill evolve 命令保留用户入口与原调用契约，由记忆服务侧适配层接入新的演进算法库。旧命令仍在原服务执行，不依赖用户的本地 UI 在线。
UI 与旧命令同时触发两者共享服务端素材占用、去重与结果记账契约。云端 Skill 的演进结果沿用云端身份保存，再同步到本地，避免生成互不关联的历史。
新算法逐步替换旧算法通过服务端版本切换启用新实现；旧轨迹、绑定和版本持续可读。涉及存储变化时提供可重复、可恢复的兼容迁移，升级失败可保留旧入口，用户不重建数据。
切换到远程运行在设置中选择远程 Skill 服务并验证能力。模型凭证由执行端管理，远程配置需权限；本地路径不能直接当远程路径使用。界面明确显示执行位置及需要上传的内容。

配置以「工作台默认、功能设置、模型连接引用」组织，由解析层转换为现有算法所需的配置。云服务保留自己的配置所有权；新旧入口共享业务契约，不要求共享同一 Python 进程。
