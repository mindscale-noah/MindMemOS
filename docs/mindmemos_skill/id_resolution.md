# Skill 与管理图谱的 ID 和解析

## 新建对象的 ID

| 对象 | 对外 ID | 解析结果 |
| --- | --- | --- |
| Skill | `sk-` 加 32 位十六进制 UUID | 当前生效的 Skill 版本 |
| Skill 版本 | `skv-` 加 32 位十六进制 UUID | 该 ID 指定的不可变版本 |
| 管理图谱 | `skg-` 加 32 位十六进制 UUID | 当前发布的图谱版本 |
| 图谱版本 | `skgv-` 加 32 位十六进制 UUID | 该 ID 指定的不可变快照 |

`skill-resolve` 接受 Skill 别名、完整 `sk-` / `skv-` ID，或同类型内唯一的 ID 前缀；`graph-resolve` 对图谱别名、`skg-` / `skgv-` 执行相同规则。别名只做完整匹配，前缀命中多条返回冲突，不会任选一条。两个接口都先应用已认证的项目范围，版本结果同时包含所属对象 ID 和 `is_current`。传入历史版本时，结果保持历史版本，不切换到当前版本。

旧 `sk_` / `v_` Skill ID 继续可读。旧图谱存储 ID 继续可作为精确引用；升级时为它补充 `skg-` 对外 ID，并以原图谱 ID 作为别名。旧图谱版本 UUID 继续存在；对应的对外 ID 是 `skgv-` 加 UUID 的 32 位十六进制表示。

## 存储兼容

新 Skill 及其版本直接以新格式写入主键。已有 Skill ID 和版本 ID 保持原值，以免改动轨迹、远端映射、图节点和外部保存的引用。图谱家族新建时使用 `skg-` 存储 ID；旧图谱保留原存储 ID，以新增的 `public_id` 和 `alias` 提供标准对外 ID 与旧引用。图谱版本继续以 UUID 作为内部关联键，并增加唯一的 `public_version_id`；图节点、边、发布指针及旧服务仍可用 UUID 关联。对外 API 一律返回 `skgv-` ID。

服务初始化时对图谱表进行可重复执行的增量迁移：增加三个可空列、分批回填旧行、建立项目内唯一索引。每批回填独立提交；PostgreSQL 唯一索引并发建立，中断产生的无效索引会在下次启动时重建。中断后可重新启动服务继续执行。旧服务在过渡期写入的新行即使没有新增列，解析器也能按旧 ID 推导对外 ID，下次初始化会回填。

## 部署顺序与恢复

1. 先以 `persistence.config.prefixed_ids: false` 和 `manage_pipeline.config.prefixed_graph_ids: false` 部署新服务，使解析逻辑和增量迁移覆盖所有实例。此阶段新旧实例继续用原格式创建 Skill/版本和图谱存储 ID，训练任务重试仍使用旧的确定性版本 ID。调用方可逐步改用新 resolve 与图谱对外 ID。
2. 确认旧版写入实例全部退出后，将两个配置设为 `true` 并滚动部署。新 Skill/版本和图谱此后直接使用新格式的存储 ID；已有对象继续保留原存储 ID 和稳定的引用。
3. 应用侧先升级 SDK 和 UI 对 `skgv-` 的接收能力，再依赖新版图谱列表、快照和推荐响应。过渡期保留旧 UUID 请求格式以供旧调用方使用。

迁移失败时，先修复数据库错误并重启新服务；重复迁移不会重建图谱或更换已分配的对外 ID。第二阶段需要回退业务代码时，回退到第一阶段的别名兼容版本并关闭两个新 ID 生成开关；已经创建的 `skg-` 图谱继续由该版本读取。不得直接回退到不认识图谱别名和对外版本 ID 的旧服务来写入这些图谱。
