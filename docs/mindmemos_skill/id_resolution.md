# Skill 与管理图谱的 ID 和解析

## 新建对象的 ID

| 对象 | 对外 ID | 解析结果 |
| --- | --- | --- |
| Skill | `sk-` 加 32 位十六进制 UUID | 当前生效的 Skill 版本 |
| Skill 版本 | `skv-` 加 32 位十六进制 UUID | 该 ID 指定的不可变版本 |
| 管理图谱 | `skg-` 加 32 位十六进制 UUID | 当前发布的图谱版本 |
| 图谱版本 | `skgv-` 加 32 位十六进制 UUID | 该 ID 指定的不可变快照 |

`skill-resolve` 接受 Skill 别名、完整 `sk-` / `skv-` ID，或同类型内唯一的 ID 前缀；`graph-resolve` 对图谱别名、`skg-` / `skgv-` 执行相同规则。别名只做完整匹配，前缀命中多条返回冲突，不会任选一条。两个接口都先应用已认证的项目范围，版本结果同时包含所属对象 ID 和 `is_current`。传入历史版本时，结果保持历史版本，不切换到当前版本。

旧 `sk_` / `v_` Skill ID 仍可作精确引用。新图家族直接使用 `skg-` 格式的 `graph_id`，alias 是项目内快捷引用，name 是展示名称。图家族不再维护第二套公共身份。

## 图存储与本地数据库

图、节点、边和快照按同一个 `graph_id` 关联。图谱版本只使用一个 `graph_version_id`，数据库以 `Text` 保存完整的 `skgv-` 字符串。当前版本指针、节点和边的版本引用，以及 Python 和 HTTP API 均使用同一个值；不再维护独立的 `public_version_id`，查询时不拆除前缀或转换为 UUID。

独立 Skill 服务尚未上线，不保留旧图表的迁移、双身份桥接或滚动部署逻辑。已有本地数据库与当前结构冲突时，按项目流程只清理该 Skill 服务本地数据库并重启。此规则不适用于 `src/mindmemos/` 的商用云服务，也不得清理云数据。
