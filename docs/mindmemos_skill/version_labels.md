# 中心仓版本别名

`skill_versions_v1.version_id` 保持不变，继续用于主外键、图谱、轨迹和审计。
`version_label` 是展示别名，在 `(project_id, skill_id)` 内唯一；`version_revision` 仍是元数据修订计数。

## 发布规则

用户标签为 `vMAJOR.MINOR.PATCH`，三段均为非负整数，不允许前导零。默认初始标签 `v1.0.0`。
`RegisterRequest.version_label` 可指定初始标签；`CommitRequest.version_label` 可指定未占用的标签。
自动提交使用 `version_bump="patch"|"minor"|"major"`，默认 patch，高位递增时低位归零。
分配时使用输入版本数字部分和同命名空间的历史最大编号，保留历史分支编号，不因切换旧版本而复用。

算法 pipeline 提交时传固定 `algorithm="treeskill"` 等标识，系统生成 `v1.2.1-treeskill`。
标识仅允许小写字母开头、后续小写字母/数字及由单个连字符分隔的片段；算法仅自动增加 patch。
算法身份应由具体 pipeline 的实现固定，不取自 UI 的用户输入或 Skill 的 implementation 字段。
当前 training/evolution 仍为抽象契约；新增命名逻辑不代表已实现自动训练或演化。

手动标签不允许尾缀，不能与非默认 version_bump 或 algorithm 混用。
标签重复返回冲突；相同标签可以存在于不同 Skill。
发布在短事务中先锁定并校验当前版本，再分配标签、插入快照、推进当前指针。
数据库唯一索引 `skill_versions_label_uq` 兜底。当前指针过期时整个提交回滚，不保留孤儿版本。
算法尾缀解决命名冲突，不取消并发更新当前版本的保护。

## 已有数据升级

升级路径：部署新版代码 → 正常执行 `await service.initialize_storage()` → 启动接入层。
默认本地 `await create_service()` 已执行该初始化。显式 YAML 组装调用方仍显式初始化。
迁移仅操作现有 v1 本地版本表的标签、审计元数据和索引，不改云服务 `src/mindmemos/` 及 remote 标签契约。
更老的物理表名或缺失列仍按既有迁移流程处理，不在这里隐式重建数据库。

迁移按 `(created_at, version_id)` 稳定顺序处理每个项目/Skill：

1. 保留合法且不重复的标签；重复标签保留最早记录的标签。
2. 空、非法和重复的其他标签分配未占用的 `v1.0.N`，预先保留所有合法历史标签，避免抢占。
3. 原标签和新标签记录在 `local_metadata.version_label_migration_v1`；已有其他元数据不变。
4. 创建唯一索引。版本 ID、快照、哈希、父子关系、时间和当前指针全部保留。

更新和建索引同属一个事务；SQLite 获取写锁，PostgreSQL 使用表级写锁。
迁移期间读取仍可进行，写入可能短暂等待数据库锁；锁超时会报错，不删除或重建数据。
中断或异常会回滚，重新启动即可重试；成功后重复执行不再次改名。
如果迁移审计键已有冲突内容，升级明确失败并保留原数据，需要检查该元数据后重试。

兼容范围：旧读取方仍能读取字符串标签；为兼容过渡期旧写入，字段保持可空。
旧写入方产生的新空标签会在下一次初始化补齐；旧的非空重复标签写入将受新唯一约束拒绝，因此自定义低层写入方应先升级到新分配接口。
原云端可重复标签保存在 remote 映射中，不被本地迁移改写。
服务不提供单版本删除或重命名；通过原生 SQL 绕过服务删除历史不属于编号保留保证。

## 验证与边界

测试覆盖已有非空数据、非法/重复/空标签、重复执行、中途异常回滚再恢复、哈希/指针/谱系保留、并发提交和唯一约束。
SQLite 已执行真实数据库验证；PostgreSQL 使用相同 SQLAlchemy 事务及索引路径，但本次未连接真实 PostgreSQL 服务器验证。
