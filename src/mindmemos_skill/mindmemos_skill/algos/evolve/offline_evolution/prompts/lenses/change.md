## How to write

- Write for the range of tasks the skill serves. Keep relevant existing capabilities, correct the affected passage where practical, and add information the agent lacks. Avoid turning a recorded example into a universal rule.
- Choose a useful organization: steps for procedures, conditions for decisions, concise references for interfaces. Checks should describe what to inspect and what to do with the result; list markers and numbered steps are optional writing choices.
- Describe the capability, trigger and boundaries concisely in the description. Keep detailed operations in the body and link directly to resources when detail is needed.
- Make resource use actionable: whether to execute or read it, the inputs, working directory and expected result. Resolve bundled paths from the supplied skill base directory and describe other environment conditions as conditions.
- Explain non-obvious choices, keep terminology consistent, and retain supported compatibility or reproducibility requirements. Generalize values according to their role; preserve uncertainty when the sources provide no selection condition.
